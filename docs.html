HEIR(7)the manual

what heir is

heir is a dead dev switch for pump.fun coins. a dev adds their coin and checks in once every 72 hours with one signature. while they do, the coin's creator fees reach them as normal. if 72 hours pass with no check-in, the switch fires and the fees pass to the coin's top 50 holders, split by bag, forever.

heir has no token and no program of its own. it's notes on Solana, a vault per coin, and the code in this repo.

the protocol

  DEV                 HEIR                  SOLANA               HOLDERS
   │                    │                      │                     │
   │── register ───────▶│ reads the creator    │                     │
   │                    │ from the bonding ───▶│                     │
   │                    │ curve                │                     │
   │◀── vault address ──│                      │                     │
   │── route fees to the vault ───────────────▶│                     │
   │── sign heir:1:register ──────────────────▶│                     │
   │                    │                      │                     │
   │   every ≤ 72h:     │                      │                     │
   │── sign heir:1:checkin ───────────────────▶│                     │
   │◀── vault pays the dev ────────────────────│                     │
   │                    │                      │                     │
   ×   72h, no check-in │                      │                     │
                        │── switch fires ──────▶│                     │
                        │── vault pays by bag ─────────────────────▶│ top 50
                        │   (on demand + daily, forever)             │

the notes

registering and checking in are one transaction each, signed by the dev wallet. each carries two instructions: a 0-SOL transfer to the heir tag address, so the note is easy to index, and a memo:

heir:1:register:<mint>   adds the coin. only counts if the signer is the coin's creator
heir:1:checkin:<mint>    resets the 72h timer. only counts if the signer is the dev

the cost is one signature plus Solana's network fee. nothing is paid to heir. the first register for a mint wins; later ones are ignored.

the switch

  1. the register note is the first beat. every check-in from the dev wallet is another beat.
  2. if the gap between two beats, or between the last beat and now, is over 72 hours, the switch fires at the last beat + 72h.
  3. a fired switch never resets. check-ins after it are ignored.
  4. check-ins signed by any other wallet are ignored.

the vault

each coin has its own vault address. its key is derived on heir's server from one secret and the coin's mint, so nothing is stored and nothing leaves the server. the code moves a vault's SOL to exactly two places:

  1. while alive: the dev wallet, when anyone presses pay or after a check-in. it keeps ◎0.001 for rent and runs at ◎0.01 or more.
  2. after it fires: the top 50 holders, by bag. it runs at ◎0.02 or more.

the heirs

at every payout heir reads every token account of the mint from the chain and adds them up by owner. then it drops:

  1. owners that are off the ed25519 curve: program accounts, pools, the bonding curve
  2. the dev wallet
  3. the vault

the 50 biggest bags left are the heirs. each one's share is its bag ÷ the 50 bags together.

payouts

payable  = vault − ◎0.001 rent − ◎0.000005 × transactions
your cut = payable × your bag ÷ the top 50 bags
cuts under ◎0.001 drop, and their share goes back to the rest
up to 18 transfers per transaction, signed by the vault

anyone can press run payout on a fired coin's page. heir also sweeps every fired vault once a day. every payout shows in the coin's ledger with its transaction.

routing the fees

pump.fun pays creator fees to the coin's creator. its fee sharing lets the creator name other wallets for those fees. to put a coin on the switch, point its creator fees at the coin's heir vault (the app shows it), or send fees there yourself. heir can't see pump.fun's settings, so the coin page shows what it can prove: the SOL that has landed in the vault.

safety

  1. the vault keys never leave the server and no page can see them.
  2. no payout takes an address from a request. recipients come from the chain: the dev from the coin's bonding curve, the heirs from the token accounts.
  3. one payout per coin at a time.
  4. the registry is public. anyone can rebuild it from the tag address.

public api

GET  /api/heir?action=config                 tag address, rules, SOL price
GET  /api/heir?action=coins                  every coin and its state
GET  /api/heir?action=coin&mint=…            one coin: beats, vault, heirs, ledger
GET  /api/heir?action=verify&mint=…&wallet=…  is this wallet the creator?
GET  /api/heir?action=tx&kind=…&mint=…&wallet=…  an unsigned register/checkin note
POST /api/heir?action=pay&mint=…             pay the vault out by the rules

check it yourself

open the tag address on Solscan: —. every coin and every check-in is there, in order. every vault's moves are on its own page. the code is in the repo.
